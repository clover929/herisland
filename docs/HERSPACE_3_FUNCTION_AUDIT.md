## P0 安全与数据保护

1. 原损坏存储读取失败后仍可覆盖：现暂停写入，不清除原值；写失败保留表单输入，未伪报成功。
2. 保存前比对上次读入的原始快照，发现他页更新先刷新并提示重试；草稿同样保护，避免盲目覆盖。
3. localStorage没有跨标签事务/原子CAS，极端同时写入仍需数据库解决；不声称多用户同步。
4. 模型API保留Origin白名单，再拒绝浏览器sec-fetch-site:cross-site；CLI无Origin保持可用。
5. JSON类型、64KB字节上限、单条/上下文限制仍在；慢请求读取可由超时/取消中止。
6. 每进程最多2个AI请求，繁忙返回统一429错误；原20次/分钟限流保留。生产多进程需共享限流，不新增云服务。
7. 模型仍只由服务端访问回环地址；地址/模型配置不发到前端，错误不泄露模型配置，无聊天日志。模型消息仅保留role/content，丢弃images/tool_calls等未知字段。回复以纯文本/受限https及站内人物链接呈现。

## AI体验与流式评估

- 95秒客户端截止时间配合原90秒服务端超时，保留取消与重试；同步in-flight锁避免同标签重复请求。
- 模式各保留messages/text/error/busy；站内导航保留内存，整页刷新清空，不将聊天写入localStorage。
- 清空仅影响当前模式，需明确确认；取消确认不丢内容。
- Explore仅使用已核实且已审核发布记录，事实编号白名单输出及来源映射不变。站内引用改Next Link，避免整页刷新清空内存会话。
- Ollama支持流式，但本轮保留非流式：目前需要最终推理草稿过滤，Explore还需解析完整事实编号；直接转发流可能暴露不合格的中间文本。流式需单独定义安全事件协议、缓冲/取消和引用终态测试，不能仅改变stream字段。
- 官方参考：https://docs.ollama.com/api/chat 和 https://docs.ollama.com/api/streaming 。
